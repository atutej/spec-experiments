## How to read it

- **Acceptance length:** the mean number of tokens accepted per target forward pass, counting the bonus token. Drafts use block size 8.
- **Generation length:** the mean number of tokens the evaluated model wrote per reply, thinking included, with the stop token. Medians are lower for every
  row (gold: 1,512 first turn, 1,015 later turn).
- **Gold reply:** the corpus's own (DeepSeek-V3.2) reply to the same 1,000 prompts, counted the same way (reply tokens + `<|im_end|>`). It has no
  acceptance length because no drafter was run on it.
- **Prompts:** 500 first-turn prompts and 500 later-turn prompts (one random later assistant turn per conversation, earlier turns taken from the
  corpus), built by `tools/eval_acceptance/build_prompts.py` from conversations that are NOT in the 100k training sample (`runs/eval_prompts_500`).
- **Sampling:** temperature 0.6, top-p 0.95, top-k 20, at most 8,192 new tokens, a fixed seed per request, concurrency 32. One run per row, no confidence intervals.
- **The 8,192 cap truncates answers:** it was hit by 8.6% (A) and 7.3% (B) of the base model's completions and by 19.7% (B on SFT) and 20.5% (C) of the SFT
  model's, so the SFT model's generation lengths are underestimates. For the gold replies 21 of 1,000 exceed 8,192.
- **Rows evaluated on different models are not a fair ranking:** the SFT model writes much longer later-turn answers (about 2,230 tokens against about 880 for
  the base model), and that text may be easier or harder to draft. Compare drafters on the same evaluated model: A against B on the base model, B against C on the SFT model.
- **Row D** is the targetgen drafter for the SFT target (responses regenerated by the SFT model). Its regeneration was still running when this table was made.

those 1,000 prompts with the Qwen3 tokenizer.
