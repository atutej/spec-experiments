# TACC Horizon

Verified on the machine on 2026-11-13 (first run: vLLM fork env build, GSM8K parity with marin-community/vllm#128). Earlier draft text came from the docs without access.

- **Nodes:** GB nodes (`c1xx-xxx`, e.g. `c128-005`): `aarch64`, 144 Grace cores, ~1.7 TB RAM, 4x GB200 (189 GB, sm_100, driver 610.57). `uname -m` was only checked on a compute node (the session was an interactive job); a login node was not checked.
- **Queues:** the partition is `debug` for now (not `gpu`/`gpu-dev`): 1000 GB nodes, `MaxTime=UNLIMITED`, `MaxNodes=UNLIMITED`, QoS `qdebug`. `debug-shared` is down. `qlimits` does not exist. Accounts: `ccr24067` and `default`; a job without `-A` ran under CCR24067.
- **Submitting:** `sbatch` is refused on compute nodes ("sbatch not available on compute nodes"): submit from a login node. `--gres`, `--gpus-per-task` are rejected and `--export` is discouraged. An interactive (idev) job cannot have its time limit raised by the user (`scontrol update` denied).
- **Network:** compute nodes have outbound internet (app.daytona.io, github.com, codeload.github.com, huggingface.co, pypi.org, repo.anaconda.com, download.pytorch.org all reachable).
- **Modules:** `cuda/12.9, 13.1, 13.2, 13.3` (13.3 loaded by default with `nvidia/26.9`), `gcc/15.3.0, 16.1.0, 16.2.0`; the system `/usr/bin/gcc` is 14.3.1 and is what the vLLM build uses. There is no gcc 14.2.0 and no python/conda/uv module (system python 3.12.14). Vista's `gcc/14.2.0` and `cuda/13.1` loads do not work here.
- **Gotcha, CUDA module vs pip nvcc:** the `cuda/13.3` module exports `CPATH`, `CUDA_PATH`, `CUDA_ROOT` (and `CUDA_HOME`). The vLLM env uses the pip toolkit (nvcc 13.2.x); with the module's headers on `CPATH` the compile fails with "CUDA compiler and CUDA toolkit headers are incompatible". `envs/vllm.sh` unsets them while building and in the env's activate hook. The libcuda link stub comes from the module (`CUDA_MODULE_HOME`).
- **Conda:** none preinstalled. Miniconda under `$SCRATCH/miniconda3` (`CONDA_ROOT` default). Envs are in `$PROJECT_ROOT/envs`.
- **Filesystems:** `$SCRATCH` (`/scratch/<id>`) has no quota and is purged after 10 days without access. `$WORK` is set (`/work/<id>/horizon`) but the docs say it is not available to early users; not used. `/tmp` is node-local (157 GB). Under `$SCRATCH/marin_speculator` and lost on a purge: `envs/` (conda envs), `wheels/` (the built vLLM wheel, ~1 h to rebuild), `cache/hf` (127 GB: Dr. Doom target + drafter), `runs/` (prompts, results), `vllm_fork_src_main/` and its build tree, `$SCRATCH/miniconda3`, and `keys.env`. Copy results and the wheel off `$SCRATCH` to keep them.
- **vLLM fork env:** `setup/machines/horizon/slurm/build_vllm_fork_env.sbatch` builds `vllm_fork` (sm_100 only, ~40 min on one node with 48 jobs). Result: vllm `0.0.0.dev20261112+marin.7fc2c6569d`, torch 2.14.1+cu132. It builds just this env (it does not call `setup.sh`, which would also clone every repo in `repos.txt`, some over ssh) and clones `speculators` over https for `hs_connectors`. The wheel goes to `$PROJECT_ROOT/wheels` (`VLLM_WHEEL_DIR` from `env.sh`).
- **GSM8K parity with marin-community/vllm#128:** served Dr. Doom + the 6-layer Grug DSpark drafter (DP4 x EP4, T=1, concurrency 16, 2048 new tokens, 8 speculative tokens, probabilistic draft + standard rejection), all 1319 prompts: acceptance length 3.851 against 3.855 in the PR (5,366 output tokens/s, server ready after 511 s, eval 208 s).
- **Running the serving evals (`tools/eval_acceptance/serve_eval.sh`):** it needs `VLLM_ENV=vllm_fork CLIENT_ENV=vllm_fork` (there is no `speculators` env here); prompts for GSM8K come from `build_paper_prompts.py`, which needs `datasets`+`transformers`+`jinja2` (a small venv, not the vLLM env).

Not verified: `uname -m` on a login node; the agentic eval (`tools/agentic_eval`, Harbor + Daytona) has not been run here; `$WORK` and `idev` options.
